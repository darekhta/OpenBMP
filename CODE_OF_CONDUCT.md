# OpenBMP Code of Conduct

OpenBMP is an academic simulation project. Project spaces are for technical
work, review, documentation, and scope discussion.

## Expected Behavior

- Be direct, respectful, and specific.
- Critique ideas, designs, data, and code rather than people.
- Keep discussions within the project's academic, simulation-only scope.
- Respect maintainer decisions on scope and provenance issues.
- Disclose conflicts of interest when reviewing scope-sensitive changes.

## Unacceptable Behavior

- Harassment, threats, personal attacks, or discriminatory language.
- Publishing private information without consent.
- Pressuring maintainers to accept content outside
  [docs/safety-boundaries.md](docs/safety-boundaries.md).
- Attempting to introduce undocumented data sources or deployment claims
  through indirect naming or downstream framing.
- Derailing technical review with unrelated political or national advocacy.

## Enforcement

Maintainers may remove comments, close issues or pull requests, block users,
or escalate to platform moderation when behavior harms the project or its
scope posture.

Scope enforcement is not a conduct sanction by itself. A maintainer
may reject a contribution on scope grounds even when the contributor acted in
good faith.

## Reporting

Report conduct concerns privately to the maintainers. Before the project has a
dedicated contact address, use the repository owner's private contact channel
or GitHub moderation tools. Do not include sensitive technical exploit details
in public conduct reports.
